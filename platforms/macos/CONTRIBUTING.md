# Contributing to VTTv2

Спасибо за интерес к проекту VTTv2! Мы приветствуем вклад от сообщества.

## Как внести вклад

### Сообщить об ошибке

Если вы нашли ошибку:
1. Проверьте, не была ли она уже сообщена в [Issues](https://github.com/FUYOH666/VoiceToText-MLX-M1-8Gb/issues)
2. Если нет - создайте новый Issue с описанием проблемы
3. Укажите шаги для воспроизведения и информацию о вашей системе

### Предложить улучшение

Если у вас есть идея для улучшения:
1. Создайте Issue с описанием предложения
2. Обсудите идею с сообществом
3. Если идея одобрена - можете реализовать её

### Добавить код

1. Fork репозитория
2. Создайте ветку для вашей функции (`git checkout -b feature/AmazingFeature`)
3. Внесите изменения
4. Убедитесь, что код соответствует стилю проекта
5. Запустите тесты (см. раздел "Тестирование")
6. Commit изменения (`git commit -m 'Add some AmazingFeature'`)
7. Push в ветку (`git push origin feature/AmazingFeature`)
8. Откройте Pull Request

## Стиль кода

- Используйте Python 3.12+
- Следуйте PEP 8 (форматирование через ruff приветствуется)
- Добавляйте docstrings для функций и классов
- Комментируйте сложную логику
- Обновляйте документацию при изменении функционала

## Тестирование

Проект использует pytest для автоматических тестов. Перед отправкой PR убедитесь, что:

### Установка зависимостей для тестирования

```bash
pip install -r requirements.txt
```

### Запуск тестов

```bash
# Все тесты
pytest tests/ -v

# Конкретный файл
pytest tests/test_config.py -v

# С покрытием кода
pytest tests/ --cov=src --cov-report=term-missing
```

### Написание новых тестов

При добавлении нового функционала, добавьте соответствующие тесты в `tests/`:

- `test_config.py` - тесты валидации конфигурации
- `test_audio.py` - тесты обработки аудио
- `test_transcription.py` - тесты транскрипции (используйте моки)
- `test_permissions.py` - тесты разрешений (используйте моки)

Пример структуры теста:

```python
def test_new_feature():
    """Тест нового функционала"""
    # Arrange
    test_data = create_test_data()
    
    # Act
    result = function_under_test(test_data)
    
    # Assert
    assert result == expected_result
```

## Проверка кода

### Линтинг и форматирование

```bash
# Проверка стиля кода
ruff check src/ tests/

# Форматирование кода
ruff format src/ tests/
```

### Health Check

Перед коммитом убедитесь, что health check проходит:

```bash
python src/main.py --health
```

## CI/CD

Проект использует GitHub Actions для автоматической проверки кода:

- При каждом push в main или PR запускаются тесты
- Проверяется линтинг и форматирование кода
- Генерируется отчет о покрытии кода

Убедитесь, что ваш код проходит все проверки перед отправкой PR.

## Версионирование

Проект следует [Semantic Versioning](https://semver.org/lang/ru/):

- **MAJOR** - breaking changes (несовместимые изменения API)
- **MINOR** - новые функции (обратно совместимые)
- **PATCH** - исправления багов (обратно совместимые)

Все изменения документируются в `CHANGELOG.md`.

## Лицензия

Внося изменения, вы соглашаетесь, что ваш код будет распространяться под лицензией MIT.
